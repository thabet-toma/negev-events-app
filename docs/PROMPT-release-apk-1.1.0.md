# برومت رفع التطبيق — نسخة 1.1.0

**لا تُشغِّل هذا قبل أن ينتهي نشر `faee329` بنجاح**
(`docs/PROMPT-deploy-faee329.md`). ترتيبهما ليس اختيارياً: الخادم الجديد يخدم
نسخة التطبيق الجديدة، والعكس لا يعمل.

انسخ كل ما تحت الخط وأعطه للوكيل.

---

رفع نسخة تطبيق موبايل جديدة على `https://munasbat.ktra-pro.tech`.

**لا تغيير في الكود ولا في قاعدة البيانات ولا في البنية.** هذا ملفٌ واحد
يُستبدَل، وثلاثة متغيّرات بيئة تُضبط. لا `git pull`، ولا ترحيل، ولا إعادة بناء
للحاوية.

## لماذا هذا مستعجل

الخادم بعد `faee329` صار يرفض من التطبيق القديم شيئين كان يقبلهما: **النشر**
(`POST /api/events`) و**التبريك** (`POST /api/events/:id/congratulate`) — كلاهما
صار خلف تسجيل الدخول، والنسخة المثبَّتة اليوم (`1.0.0`) لا ترسل رمزاً فيهما.
والتطبيق القديم أيضاً **لا يرى إلا الأعراس**، لأن طلبه بلا ترويسة
`X-App-Version`.

فحتى تتمّ هذه الخطوة، **مستخدم التطبيق يفتحه فيجد النشر معطَّلاً بلا تفسير**.
هذه الخطوة هي التفسير.

## ما ستفعله بالضبط

استبدال `server/downloads/negev-events.apk`، وضبط ثلاثة متغيّرات في `.env`،
وإعادة تشغيل الحاوية **لأجل المتغيّرات وحدها** — لا لأجل الملف.

**الملف لا يحتاج إعادة تشغيل.** `docker-compose.yml` يربط المجلّد ربطاً حيّاً
(`./server/downloads:/app/downloads`)، فما تكتبه على المضيف تخدمه الحاوية
فوراً. المتغيّرات وحدها تُقرأ عند إقلاع العملية، فهي سبب إعادة التشغيل.

## ١. تأكّد أنّ الأرضية صحيحة قبل أن تلمس شيئاً

```bash
cd <app-dir>
git log --oneline -1        # يجب أن يظهر faee329 أو أحدث
curl -s https://munasbat.ktra-pro.tech/api/app/version
```

**إن لم يكن `faee329` مطبَّقاً بعد: قف وأبلغ.** رفع تطبيق يتحدّث لغة خادم لم
يُنشر بعد يكسر النسخة الجديدة كما كسر القديمة.

سجّل ما يعيده `/api/app/version` الآن — ستقارن به.

## ٢. احتفظ بالقديم قبل أن تستبدله

```bash
ls -la server/downloads/
cp server/downloads/negev-events.apk ~/negev-events-1.0.0.apk.bak
ls -lh ~/negev-events-1.0.0.apk.bak
```

هذه نقطة تراجعك الوحيدة لملف التطبيق. لا تكمل إن فشلت.

## ٣. ضع الملف الجديد

الملف الجديد يصل من جهاز المالك (`app-release.apk`، نحو 55 ميغابايت). إن لم
يكن قد وصل بعد، فأمر النقل من جهازه:

```bash
scp app-release.apk <user>@<host>:<app-dir>/server/downloads/negev-events.apk
```

**الاسم على السيرفر يجب أن يبقى `negev-events.apk` حرفياً** — هو ما يشير إليه
`APP_APK_URL`، وتغييره يكسر الرابط عند كل مستخدم.

ثم تحقّق أنه وصل كاملاً وأنه فعلاً الجديد:

```bash
ls -lh server/downloads/negev-events.apk
sha256sum server/downloads/negev-events.apk
```

**قارن البصمة بالتي أعطاك إياها المالك.** ملف APK مقطوع ينزل عند المستخدم
ويفشل تثبيته بلا رسالة مفهومة — والبصمة هي ما يمنع ذلك.

## ٤. اضبط المتغيّرات

في `.env` بجانب `docker-compose.yml`:

```
APP_LATEST_VERSION=1.1.0
APP_RELEASE_NOTES=أنواع مناسبات جديدة: عزا، خطوبة، نجاح، حج وعمرة · هوية جديدة · عارض ستوري · صفحة «مناسباتي» لتعديل ما نشرته
```

**`APP_MIN_VERSION` تُترك فارغة عن قصد — التحديث تنبيه، لا إلزام.**
ضبطها على `1.1.0` يقفل التطبيق كلّه في وجه من لم يحدّث بعد، بمن فيهم من يريد
تصفّح الأعراس فقط — وهي ما زالت تعمل عنده. وتنصيب APK خارج المتجر يتطلّب تفعيل
«مصادر غير معروفة»، فالإلزام الفوري احتكاك حقيقي لا مجرد ضغطة.

هذا يتّسق مع [[0004-self-hosted-app-updates]]: «`min_version` يبقى في غمده».

الثمن المقبول: من لا يحدّث يجد النشر والتبريك يفشلان (401). المراقَبة بعد النشر
هي ما يقرّر إن كان يستحق التصعيد لاحقاً — وعندها يكفي إضافة سطر واحد
(`APP_MIN_VERSION=1.1.0`) وإعادة التشغيل، بلا بناء ولا رفع.

**لا تضف ولا تعدّل أي متغيّر آخر.** إن وجدت `APP_APK_URL` غير موجود، أضفه
كما هو في `server/.env.example`:

```
APP_APK_URL=/downloads/negev-events.apk
```

## ٥. أعد التشغيل — للمتغيّرات، لا للملف

```bash
docker compose up -d
```

**بلا `--build`.** لا كود تغيّر.

## ٦. تحقّق

```bash
curl -s https://munasbat.ktra-pro.tech/api/app/version
```

المتوقَّع: `latest_version` تساوي `"1.1.0"`، و`min_version` تساوي `null`، و`apk_url`
**رابط مطلق على النطاق الحقيقي** — إن ظهرت فيه `localhost` فـ`PUBLIC_URL`
غير صحيحة ولن ينزّل أحد شيئاً.

```bash
curl -sI https://munasbat.ktra-pro.tech/downloads/negev-events.apk | head -3
```

المتوقَّع: `200` وطول محتوى يطابق حجم الملف.

ثم نزّله فعلاً وتأكّد أنه ليس صفحة خطأ بحجم ملف:

```bash
curl -s -o /tmp/check.apk https://munasbat.ktra-pro.tech/downloads/negev-events.apk
sha256sum /tmp/check.apk        # يجب أن يطابق بصمة الخطوة ٣
rm /tmp/check.apk
```

**البصمة المطابقة هي الدليل الوحيد المقبول** أنّ ما يصل المستخدم هو ما رفعته.

وفي المتصفح: زرّ تنزيل التطبيق في ترويسة الموقع يبدأ تنزيلاً فعلياً.

## التراجع

```bash
cp ~/negev-events-1.0.0.apk.bak <app-dir>/server/downloads/negev-events.apk
```

وأفرغ `APP_LATEST_VERSION` و `APP_MIN_VERSION` في `.env` ثم
`docker compose up -d`. إفراغهما يُسكِت فحص التحديث تماماً بدل أن يشير إلى
نسخة تراجعتَ عنها.

## أبلغ عند الانتهاء

بالنصّ الحقيقي لا بالوصف:

1. ما أعاده `/api/app/version` **قبل** و**بعد**.
2. حجم ملف النسخة الاحتياطية، وحجم الملف الجديد.
3. البصمتان: بصمة الملف على القرص، وبصمة ما نزّلته من الرابط — **صراحةً هل
   تطابقتا**.
4. ترويسة `curl -sI` على رابط الـAPK.
5. **أي شيء توقّفت عنده وأبلغت بدل أن تحلّه.**
