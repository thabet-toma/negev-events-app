(يحتاج SSH للسيرفر، وملف APK مبنيّاً محلياً وموجوداً فعلاً على القرص).

**لا توجد خطوة إنسان قبل البدء في هذا الإصدار.** لا مفاتيح جديدة، ولا ترحيل
قاعدة بيانات، ولا متغيّر بيئة جديد — الوكيل يعدّل سطرين قائمين في `.env` لا غير.

## قواعد لا تُكسر

1. **لا تقرأ `.env` ولا تطبع محتواه ولا تنسخ أي قيمة منه إلى أي ملف أو رسالة.**
   ستعدّل فيه سطرين بأداة تحرير موضعية — وهذا كل تعاملك معه.
2. **لا تلمس `APP_MIN_VERSION` إطلاقاً.** رفعه يجبر كل مستخدم على التحديث قبل
   أن يفتح التطبيق، وليس في هذا الإصدار أي تغيير كاسر يبرّره.
3. **لا تشغّل `npm test` على السيرفر** — يرفض العمل عند `NODE_ENV=production`
   ويكتب بيانات تجريبية.
4. **لا تحذف أي شيء من `/app/uploads`** — ملصقات مناسبات قائمة.
5. **عند أي نتيجة مخالفة للمتوقَّع: توقّف فوراً، لا تُصلح من عندك، وأبلغ.**
6. الأجزاء الثلاثة بالترتيب. **أنجِز كل جزء كاملاً وأبلغ، ثم انتظر إذناً للتالي.**

## ما الذي تنشره

ثلاثة أشياء، وكلها مرئية بالعين:

**١. كرت المناسبة صار شاشة كاملة، والملصق يملؤه.** كان الكرت صندوقاً ٤:٥ فوقه
شريط مطموس وتحته شريط مطموس — الصورة تظهر بين ضبابيتين كأنها في مرآة. صار
الملصق يملأ الكرت كلّه داخل إطار ذهبي، والتمرير يقف عند **كرت واحد** لكل حركة
إصبع (‏`scroll-snap` في الويب، `PageView` في التطبيق). والتعميمات وزرّ «المزيد»
خرجا من داخل الحاوية القافزة — إبقاؤهما فيها كان سيجعلهما غير قابلين للوصول
أصلاً، لأن القفز الإلزامي لا يتوقّف عند طفل لا يحمل نقطة قفز.

**٢. علامة التطبيق تغيّرت.** الخيمة داخل الطوق المرصَّع صارت **خاتماً ذهبياً
محزَّزاً، فصّه مرصَّع على الشريط، وداخله كلمة «عرس»**. ٢٥ ملف PNG و`icon.svg`
أُعيد توليدها كلها من التعريف الواحد في `server/src/utils/brandMark.js`.

**٣. لا شيء في الـAPI تغيّر.** ولا مسار جديد، ولا عمود، ولا جدول، ولا ترحيل.
`mobile/lib/api/negev_api.dart` و`mobile/lib/config.dart` **لم يُمَسّا بحرف**.

### ما الذي يستوجب إعادة بناء الحاوية

`server/src/utils/brandMark.js` (العلامة) و`brandWord.js` (كلمة «عرس» مساراً
متّجهاً) و`shareCard.service.js` و`share.routes.js` تغيّرت — وكلها تُنسَخ **داخل
الصورة** (‏`COPY . .` في `server/Dockerfile`)، فـ`git pull` وحده لا يغيّر ما
يعمل داخل الحاوية.

> ⚠️ **استعمل `docker compose up -d --build app` لا `up -d app` وحده.**
> بلا `--build` تُعاد الحاوية من الصورة القديمة، فتظهر بطاقة المشاركة بالخيمة
> القديمة بينما الويب يعرض الخاتم الجديد — وكل أمر في الشاشة يبدو ناجحاً.

`server/package.json` اكتسب `harfbuzzjs` و`opentype.js` في **`devDependencies`
فقط**، والصورة تبني بـ`npm ci --omit=dev`. فهما لا يُنزَّلان على السيرفر ولا
يحتاجهما التشغيل: كلمة «عرس» مسار ثابت مُلتزَم في المستودع، والمكتبتان أداتا
توليد على جهاز المطوّر لا غير. **إن رأيت البناء يحاول تنزيلهما فشيء ما خطأ —
قف وأبلغ.**

# الجزء الأول — النسخة الاحتياطية، السحب، وإعادة البناء

**١. النسخة الاحتياطية أولاً — قبل أي سحب وقبل أي إعادة تشغيل:**

```
ssh -i ~/.ssh/hostenger2/id_ed25519 root@munasbat.ktra-pro.tech \
  'cd /root/munasbat/app && docker exec negev_events_mysql sh -c "mysqldump -u root -p\"\$MYSQL_ROOT_PASSWORD\" --single-transaction --routines negev_events" > ~/negev-backup-before-1.7.0.sql && tail -1 ~/negev-backup-before-1.7.0.sql && ls -l ~/negev-backup-before-1.7.0.sql'
```

السطر الأخير يجب أن يكون `-- Dump completed`، والحجم غير صفري. إن لم يكن:
**قف وأبلغ، ولا تكمل.**

**٢. سجّل نقطة التراجع — الـcommit الحالي على السيرفر قبل السحب:**

```
ssh -i ~/.ssh/hostenger2/id_ed25519 root@munasbat.ktra-pro.tech \
  'cd /root/munasbat/app && git rev-parse --short HEAD && git status --short'
```

**اكتب هذا الـSHA في تقريرك** — هو نقطة التراجع الوحيدة. المتوقَّع `3bcc12e`؛
إن كان غيره فالسيرفر ليس حيث تظنّه — **قف وأبلغ**. وجود
`docker-compose.override.yml` غير متتبَّع أمر طبيعي — اتركه.

**٣. اسحب:**

```
ssh -i ~/.ssh/hostenger2/id_ed25519 root@munasbat.ktra-pro.tech \
  'cd /root/munasbat/app && git pull origin main && git log --oneline -1'
```

المتوقَّع أن ينتهي عند **نفس الـcommit الذي يعرضه `git log --oneline -1` في نسختك
المحلية من `main`** — تحقّق من ذلك قبل أن تتابع، لا بعد.

⚠️ السحب يحدّث `web/` **فوراً** (nginx يربط المجلد بالقرص للقراءة، بلا بناء).
فمن هذه اللحظة حتى انتهاء الخطوة ٤ يكون الموقع الجديد يخاطب خادماً قديماً —
غير ضارّ هنا لأن الـAPI لم يتغيّر، لكن **لا تتوقّف بينهما** على أي حال.

**٤. أعد البناء وأعد التشغيل، ثم اقرأ السجلّ:**

```
ssh -i ~/.ssh/hostenger2/id_ed25519 root@munasbat.ktra-pro.tech \
  'cd /root/munasbat/app && docker compose up -d --build app && sleep 25 && docker compose logs --tail=40 app'
```

المتوقَّع: بناء ينتهي بنجاح، ثم إقلاع نظيف. **لا يوجد ترحيل جديد في هذا
الإصدار** — سطور `[migrations]` القديمة تظهر كما هي وهذا صحيح، والجديد الوحيد
هو غياب أي خطأ.

🛑 إن فشل البناء أو ظهر خطأ SQL: **قف فوراً وأبلغ بنصّ السجلّ كاملاً.** لا تعِد
التشغيل مرّة ثانية على أمل أن ينجح.

**٥. تحقّق من الخادم — أربعة فحوص، قارن كل واحد بالمتوقَّع:**

```
curl -s https://munasbat.ktra-pro.tech/api/app/version
curl -s -o /dev/null -w "%{http_code}\n" "https://munasbat.ktra-pro.tech/api/events?limit=5"
curl -s https://munasbat.ktra-pro.tech/api/settings/public
curl -s https://munasbat.ktra-pro.tech/health
```

المتوقَّع: النسخة **لا تزال `1.6.0`** — هذا صحيح لا خطأ، نرفعها في الجزء الثالث
بعد وصول الـAPK. والباقي `200` واستجابات سليمة.

**٦. الفحص الذي يمسك العلامة فعلاً — بطاقة المشاركة:**

خذ `id` أي مناسبة قائمة من نتيجة `/api/events` أعلاه، ثم:

```
curl -s "https://munasbat.ktra-pro.tech/e/<ID>" | grep -c "mark-svg"
```

يجب أن يكون `1` على الأقل. ثم **افتح `https://munasbat.ktra-pro.tech/e/<ID>` في
متصفّح وانظر إلى العلامة أسفل البطاقة بعينك**: يجب أن ترى **خاتماً ذهبياً فيه
كلمة «عرس»**، لا خيمة. هذا هو الفحص الوحيد الذي يثبت أن `--build` عمل فعلاً؛
أي أمر يمرّ بلا أن تنظر لا يثبت شيئاً هنا.

**٧. الويب — انظر بعينك، لا بـ`curl`:**

افتح `https://munasbat.ktra-pro.tech` بتحديث قسريّ (‏`Ctrl+Shift+R`؛ الأصول
تُخدَم بلا بصمة نسخة، فتحديث عادي قد يعطيك `styles.css` القديم). تحقّق من
**أربعة** أشياء:

1. كل كرت يملأ الشاشة، **بلا شريط مطموس فوق الصورة ولا تحتها**
2. الملصق يظهر كاملاً داخل إطار ذهبي — لا مقصوصاً ولا محشوراً
3. تمريرة إصبع واحدة تنقلك **كرتاً واحداً بالضبط**، لا اثنين ولا نصف كرت
4. أيقونة الموقع في تبويب المتصفّح = الخاتم الجديد

🛑 إن ظهر شريط مطموس أو توقّف التمرير بين كرتين: **قف وأبلغ قبل الجزء الثاني.**

# الجزء الثاني — رفع الـAPK (لا تبدأه بلا إذن صريح)

⚠️ **الترتيب هنا ليس تفصيلاً:** ملف الـAPK يجب أن يصل مكانه **قبل** رفع
`APP_LATEST_VERSION`. عكسُ الترتيب يجعل التطبيقات القائمة ترى تحديثاً متاحاً
وتنزّل **الملف القديم** — ولا شيء في النظام يكتشف ذلك.

**١. تأكّد أن الملف المحلي هو ما تظنّه** — قبل النسخ لا بعده:

```
ls -l "mobile/build/app/outputs/flutter-apk/app-release.apk"
```

**الملف المبنيّ والمُتحقَّق منه محلياً هو هذا بالضبط** — قارن الأربعة ولا تقبل غيرها:

| | |
|---|---|
| الحجم | `60282924` بايت |
| MD5 | `65420d6c30c8af36e61446c649fb65ce` |
| النسخة داخل الملف | `versionName=1.7.0` · `versionCode=9` |
| التوقيع | `CN=thabet toma` — مفتاح الإصدار لا مفتاح التنقيح |

إن اختلف أيٌّ من هذه: **قف وأبلغ**، ولا تبنِ من عندك.

**٢. انسخه** (المجلد مربوط بالقرص في `docker-compose.yml` عبر
`./server/downloads:/app/downloads`، فلا حاجة لإعادة تشغيل الحاوية بعده):

```
scp -i ~/.ssh/hostenger2/id_ed25519 \
  "mobile/build/app/outputs/flutter-apk/app-release.apk" \
  root@munasbat.ktra-pro.tech:/root/munasbat/app/server/downloads/negev-events.apk
```

**٣. تحقّق أن الأحجام الثلاثة متطابقة** — المحلي، وعلى السيرفر، وما يخدمه HTTP:

```
ls -l "mobile/build/app/outputs/flutter-apk/app-release.apk"
ssh -i ~/.ssh/hostenger2/id_ed25519 root@munasbat.ktra-pro.tech 'ls -l /root/munasbat/app/server/downloads/negev-events.apk'
curl -sI https://munasbat.ktra-pro.tech/downloads/negev-events.apk | grep -iE "^HTTP/|^content-length|^last-modified"
```

الثلاثة يجب أن تحمل **نفس عدد البايتات بالضبط** (`60282924`)، و`last-modified`
من اليوم. ثم الفحص القاطع — البصمة على السيرفر:

```
ssh -i ~/.ssh/hostenger2/id_ed25519 root@munasbat.ktra-pro.tech 'md5sum /root/munasbat/app/server/downloads/negev-events.apk'
```

يجب أن تكون `65420d6c30c8af36e61446c649fb65ce` حرفاً بحرف. اختلافها يعني نسخاً
ناقصاً أو ملفاً آخر — **أعد النسخ، ولا تكمل**.

# الجزء الثالث — إعلان النسخة (لا تبدأه بلا إذن صريح، وبعد نجاح الجزء الثاني)

**١. عدّل سطرين في `.env`، ولا تقرأ غيرهما:**

```

```

**٢. أعد التشغيل** (‏`.env` يُقرأ عند الإقلاع فقط؛ لا `--build` هنا لأن الكود لم

  'cd /root/munasbat/app && docker compose up -d app && sleep 20 && docker compose logs --tail=20 app'

**٣. تحقّق:**

```

```

المتوقَّع: `"latest_version":"1.7.0"` · `"min_version":null` (لم يُمَسّ) ·
`apk_url` يبدأ بـ`https://` لا بـ`/`.

**٤. اطلب من الإنسان** تثبيت الـAPK على هاتف أندرويد حقيقي وتأكيد **خمسة** أشياء
بعينه — لا واحد منها يمسكه أي اختبار آلي:

1. **أيقونة التطبيق** في درج التطبيقات = خاتم ذهبي فيه «عرس»، **وقناع الأندرويد

2. كل مناسبة تملأ الشاشة، بلا شريط مطموس فوقها ولا تحتها
3. تمريرة إصبع واحدة = كرت واحد، تتوقّف عليه ولا تنزلق لاثنين
4. **السحب للتحديث لا يزال يعمل** رغم التمرير القافز — هذا أكثر ما يُخشى كسره
5. إشعار التحديث يظهر لمن عنده `1.6.0`، والتنزيل يعطيه الملف الجديد

## التراجع

- **الجزء الثالث:** أعد `APP_LATEST_VERSION` إلى `1.6.0` ثم `docker compose up -d app`.
- **الجزء الثاني:** أعد نسخ الـAPK السابق — احتفظ بنسخة منه قبل أن تكتب فوقه إن
  أردت هذا الخيار ممكناً أصلاً.
- **الجزء الأول:** `git reset --hard <SHA المسجَّل في الخطوة ٢>` ثم
  `docker compose up -d --build app`. **`--build` ضروري في التراجع أيضاً** للسبب
  نفسه الذي جعله ضرورياً في النشر.
- قاعدة البيانات لم تتغيّر في هذا الإصدار، فالنسخة الاحتياطية تأمين لا خطوة
  متوقَّعة.

- SHA نقطة التراجع
- ناتج كل `curl` كما جاء، لا ملخَّصاً
- الأحجام الثلاثة للـAPK
- **ماذا رأيت بعينك** على `/e/<ID>` وعلى الصفحة الرئيسية — لا «تمّ» بل وصف
