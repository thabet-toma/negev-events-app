## قواعد لا تُكسر

1. **لا تقرأ `.env` ولا تطبع محتواه ولا تنسخ أي قيمة منه إلى أي ملف أو رسالة.**
   ستعدّل فيه سطرين بأداة تحرير موضعية — وهذا كل تعاملك معه.
2. **لا تلمس `APP_MIN_VERSION` إطلاقاً.** رفعه يجبر كل مستخدم على التحديث قبل
   أن يفتح التطبيق، وليس في هذا الإصدار أي تغيير كاسر يبرّره.
3. **لا تشغّل `npm test` على السيرفر** — يرفض العمل عند `NODE_ENV=production`
   ويكتب بيانات تجريبية.
4. **لا تحذف أي شيء من `/app/uploads`** — ملصقات مناسبات قائمة.
5. **لا تعِد بناء الـAPK ولا ترفعه.** الملف الصحيح مكانه (تفاصيله في الجزء
   الثاني). أي بناء جديد يغيّر البصمة بلا سبب.
6. **عند أي نتيجة مخالفة للمتوقَّع: توقّف فوراً، لا تُصلح من عندك، وأبلغ.**
7. الأجزاء الثلاثة بالترتيب. **أنجِز كل جزء كاملاً وأبلغ، ثم انتظر إذناً للتالي.**

## ما الذي تنشره

### ١. إصلاح العطل — المناسبات كانت تختفي من الموقع

على 390×844 كانت التغذية تبدأ بعد **630px** من الكروم فوقها، فلا يبقى منها داخل
الشاشة إلا **145px**. الكروت موجودة في الـDOM وغير مرئية.

سببان متراكبان، وكلٌّ منهما يُبطل إصلاح الآخر لو صُلِّح وحده:

- **الحساب** كان يطرح إزاحة التغذية عن أعلى **المستند**، فيدخل فيه شريط
  التعميم والستوريات ورقاقتا الفلتر وشريط البحث (421px) — وكلها `static` تمرّ
  عند التمرير ولا تشغل الشاشة بعده. الثابت فعلاً هو الترويسة `sticky` والشريط
  السفلي `fixed` لا غير.
- **وهذا الحساب كان بلا أثر أصلاً**: `#tabHome` كان `display: flex`، فمقاس
  التغذية يأتي من `flex-basis: auto` أي من حجم المحتوى — وحجمه كرتٌ بملء
  الشاشة — فيخرج الصندوق 100dvh مهما قالت `height`.

الإصلاح: تخطيط كتلي بدل flex، والتغذية `position: sticky` تحت الترويسة، والقياس
بالبكسل من الكروم الثابت وحده، و`ResizeObserver` بدل `resize` وحده، وأرضية أمان
(`min-height: 60dvh`) لا تعتمد على أي حساب.

### ٢. الكرت بملء الشاشة وعلامة «عرس» (‎1.7.0)

الملصق يملأ الكرت داخل إطار ذهبي بلا شريطين مطموسين، والتمرير يقف عند كرت واحد.
والخيمة صارت خاتماً ذهبياً داخله كلمة «عرس» — ٢٥ ملف PNG و`icon.svg` أُعيد
توليدها من التعريف الواحد في `server/src/utils/brandMark.js`.

**لا شيء في الـAPI تغيّر**: لا مسار، ولا عمود، ولا جدول، ولا ترحيل.

### ما الذي يستوجب إعادة بناء الحاوية

`brandMark.js` و`brandWord.js` و`shareCard.service.js` و`share.routes.js` تُنسَخ
**داخل الصورة** (‏`COPY . .` في `server/Dockerfile`)، فـ`git pull` وحده لا يغيّر
ما يعمل داخل الحاوية.

> ⚠️ **استعمل `docker compose up -d --build app` لا `up -d app` وحده.**
> بلا `--build` تُعاد الحاوية من الصورة القديمة، فتظهر بطاقة المشاركة بالخيمة
> القديمة بينما الويب يعرض الخاتم الجديد — وكل أمر في الشاشة يبدو ناجحاً.

`server/package.json` اكتسب `harfbuzzjs` و`opentype.js` في **`devDependencies`
فقط**، والصورة تبني بـ`npm ci --omit=dev`، فلا يُنزَّلان على السيرفر ولا
يحتاجهما التشغيل. **إن رأيت البناء يحاول تنزيلهما فشيء ما خطأ — قف وأبلغ.**

# الجزء الأول — النسخة الاحتياطية، السحب، وإعادة البناء

**١. النسخة الاحتياطية أولاً — قبل أي سحب وقبل أي إعادة تشغيل:**

```
ssh -i ~/.ssh/hostenger2/id_ed25519 root@munasbat.ktra-pro.tech \
  'cd /root/munasbat/app && docker exec negev_events_mysql sh -c "mysqldump -u root -p\"\$MYSQL_ROOT_PASSWORD\" --single-transaction --routines negev_events" > ~/negev-backup-before-1.7.0.sql && tail -1 ~/negev-backup-before-1.7.0.sql && ls -l ~/negev-backup-before-1.7.0.sql'
```

السطر الأخير يجب أن يكون `-- Dump completed`، والحجم غير صفري. إن لم يكن:
**قف وأبلغ، ولا تكمل.**

**٢. سجّل نقطة التراجع — الـcommit الحالي على السيرفر قبل السحب:**

```
ssh -i ~/.ssh/hostenger2/id_ed25519 root@munasbat.ktra-pro.tech \
  'cd /root/munasbat/app && git rev-parse --short HEAD && git status --short'
```

**اكتب هذا الـSHA في تقريرك** — هو نقطة التراجع الوحيدة. وجود
`docker-compose.override.yml` غير متتبَّع أمر طبيعي — اتركه.

**٣. اسحب:**

```
ssh -i ~/.ssh/hostenger2/id_ed25519 root@munasbat.ktra-pro.tech \
  'cd /root/munasbat/app && git pull origin main && git log --oneline -1'
```

المتوقَّع أن ينتهي عند **نفس الـcommit الذي يعرضه `git log --oneline -1` في
نسختك المحلية من `main`** — تحقّق من ذلك قبل أن تتابع، لا بعد.

⚠️ السحب يحدّث `web/` **فوراً** (nginx يربط المجلد بالقرص للقراءة، بلا بناء) —
**وهذه هي اللحظة التي يُصلَح فيها العطل**. الخادم لا يزال قديماً حتى الخطوة ٤،
وهذا غير ضارّ لأن الـAPI لم يتغيّر، لكن **لا تتوقّف بينهما** على أي حال.

**٤. أعد البناء وأعد التشغيل، ثم اقرأ السجلّ:**

```

  'cd /root/munasbat/app && docker compose up -d --build app && sleep 25 && docker compose logs --tail=40 app'
```

المتوقَّع: بناء ينتهي بنجاح، ثم إقلاع نظيف. **لا يوجد ترحيل جديد في هذا
الإصدار** — سطور `[migrations]` القديمة تظهر كما هي وهذا صحيح، والجديد الوحيد
هو غياب أي خطأ.

🛑 إن فشل البناء أو ظهر خطأ SQL: **قف فوراً وأبلغ بنصّ السجلّ كاملاً.**

**٥. تحقّق أن الإصلاح وصل فعلاً — الفحص الوحيد الذي يمسكه:**

يجب أن يكون **‏1 أو أكثر**. إن كان `0` فالسحب لم يصل `web/` — **قف وأبلغ**.

المتوقَّع: النسخة **لا تزال `1.6.0`** — هذا صحيح لا خطأ، نرفعها في الجزء الثالث.
والباقي `200` واستجابات سليمة.

**٧. الفحص الذي يمسك العلامة — بطاقة المشاركة:**

خذ `id` أي مناسبة من نتيجة `/api/events` أعلاه، ثم **افتح
`https://munasbat.ktra-pro.tech/e/<ID>` في متصفّح وانظر إلى العلامة أسفل البطاقة
بعينك**: يجب أن ترى **خاتماً ذهبياً فيه كلمة «عرس»**، لا خيمة. هذا هو ما يثبت
أن `--build` عمل فعلاً؛ أي أمر يمرّ بلا أن تنظر لا يثبت شيئاً هنا.

**٨. الويب — انظر بعينك على مقاس هاتف، لا على سطح المكتب وحده:**

افتح `https://munasbat.ktra-pro.tech` بتحديث قسريّ (‏`Ctrl+Shift+R`؛ الأصول
تُخدَم بلا بصمة نسخة)، ثم **شغّل محاكاة جهاز على 390×844**. تحقّق من خمسة أشياء:

1. **المناسبات ظاهرة أصلاً** — هذا هو العطل الذي جئت لإصلاحه
2. الكرت يملأ الشاشة بعد تمريرة واحدة لأسفل، بلا شريط مطموس فوقه ولا تحته
3. الملصق كامل داخل إطار ذهبي — لا مقصوصاً ولا محشوراً
4. تمريرة واحدة تنقلك **كرتاً واحداً بالضبط**، لا اثنين ولا نصف كرت
5. أيقونة الموقع في تبويب المتصفّح = الخاتم الجديد

وفحص عدديّ قاطع، الصقه في وحدة التحكّم:

```
(() => { const f = document.getElementById('eventsContainer');
  return { feedH: Math.round(f.getBoundingClientRect().height),
           pct: Math.round(f.getBoundingClientRect().height / innerHeight * 100) + '%',
           cards: f.querySelectorAll(':scope > .event-card').length }; })()
```

`pct` يجب ألّا تقلّ عن **60%**، و`cards` أكبر من صفر. **إن قلّت: قف وأبلغ.**

🛑 إن ظهر شريط مطموس أو توقّف التمرير بين كرتين: **قف وأبلغ قبل الجزء الثاني.**

## التراجع

- **الجزء الثالث:** أعد `APP_LATEST_VERSION` إلى `1.6.0` ثم `docker compose up -d app`.
