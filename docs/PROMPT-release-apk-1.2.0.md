# برومت رفع التطبيق — نسخة 1.2.0+4

**لا تُشغِّل هذا قبل أن ينتهي نشر `0534f85` بنجاح**
(`docs/PROMPT-deploy-0534f85.md`)، وتحديداً قبل أن يعود التحقّق الرابع فيه
بصفر. ترتيبهما ليس اختيارياً: التطبيق الجديد يستهلك مسارات `/api/services/*`
التي لا وجود لها على الخادم القديم.

هذا الملف قسمان: **(أ)** تبنيه أنت على جهازك، **(ب)** ينفّذه الوكيل على السيرفر.

---

# (أ) البناء والتوقيع — على جهاز المالك

## ١. تأكّد من الأرضية

```bash
cd "<repo>"
git checkout main && git pull origin main
git log --oneline -1                 # يجب أن يظهر 28c641a أو أحدث
grep '^version' mobile/pubspec.yaml  # يجب أن يظهر 1.2.0+4
```

النسخة مرفوعة في المستودع أصلاً — **لا تعدّلها يدوياً**.

## ٢. ابنِ — والوسيط ليس اختيارياً

```bash
cd mobile
flutter clean
flutter pub get
flutter build apk --release --dart-define=API_BASE=https://munasbat.ktra-pro.tech
```

`--dart-define` هو الفرق بين تطبيق يعمل وتطبيق يُثبَّت ولا يصل الخادم أبداً.
بدونه يقع البناء على القيمة الاحتياطية في `lib/config.dart`
(`http://10.0.2.2:3000`) — عنوان المضيف كما يراه محاكي أندرويد، ولا شيء على
هاتف حقيقي. **هذا ما حدث فعلاً في 1.1.0+2**، وبُني الحارس في الخطوة التالية
بسببه.

## ٣. وقّع بالسكربت — لا بغيره

```bash
./scripts/sign-release.sh
```

السكربت يفعل ثلاثة أشياء لا يجوز الالتفاف على أيٍّ منها:

1. **يقرأ العنوان من الثنائي المبنيّ نفسه** (‏`libapp.so`)، ويرفض التوقيع إن لم
   يجد `https://munasbat.ktra-pro.tech` أو إن وجد `10.0.2.2` أو `localhost`.
   المصدر ليس دليلاً هنا — الثنائي هو الدليل.
2. **يوقّع بمفتاحين مع نسب (lineage)**، فيقبل أندرويد 13+ المفتاح الجديد ويقبل
   أندرويد 7‏–12 المفتاح القديم. توقيعٌ بمفتاح الإصدار وحده — أي ما يخرج من
   gradle مباشرةً — **يكسر التحديث على كل جهاز أقدم من أندرويد 13**، فيرى
   مفتاحاً لا يعرفه ويرفض التثبيت.
3. **يطبع بصمة SHA‑256.** انسخها؛ الوكيل سيقارنها بعد الرفع.

إن خرج السكربت بخطأ، **لا ترفع شيئاً** — أعد البناء كما يقول لك.

## ٤. جرّبه قبل أن ترفعه

ثبّت الملف على هاتف حقيقي **فوق نسخة 1.1.0 مثبَّتة**، لا على جهاز نظيف:

- التحديث يتمّ بلا مسح ولا إعادة تنزيل ← النسب سليم.
- تاب **«الخدمات»** ظاهر، والشريط خمس وجهات وزرّ عائم في الوسط.
- الدليل يفتح ويقول إنه فارغ بلا خطأ ← الخادم الجديد يستجيب.
- نشر مناسبة في **«القرى والتجمعات»** يطلب اختيار قرية.

الملف الناتج:
`mobile/build/app/outputs/flutter-apk/app-release.apk` (نحو ٥٥–٥٨ ميغابايت).

## ٥. ارفعه

الدومين `munasbat.ktra-pro.tech`. **اسم المستخدم ومسار التطبيق على السيرفر لا
أعرفهما** — ضعهما مكان `<user>` و `<app-dir>`، وهما نفساهما اللذان استعملتهما
في نشرة `0534f85`.

```bash
scp mobile/build/app/outputs/flutter-apk/app-release.apk <user>@munasbat.ktra-pro.tech:/tmp/negev-events-1.2.0.apk
```

رفعناه إلى `/tmp` قصداً، لا فوق الملف الحيّ مباشرةً: الوكيل يأخذ نسخة احتياطية
من القديم أولاً ثم ينقله في مكانه. رفعٌ مباشر فوق `negev-events.apk` يترك
المستخدمين على ملف نصف مرفوع طوال مدة النقل.

ثم أعطِ الوكيل على السيرفر كل ما تحت الخط، وأعطه البصمة من الخطوة ٣.

# (ب) للوكيل على السيرفر

---

استبدال ملف تطبيق الموبايل على `https://munasbat.ktra-pro.tech` وضبط ثلاثة
متغيّرات بيئة.

**لا `git pull`، ولا ترحيل قاعدة بيانات، ولا إعادة بناء لحاوية.** ملف يُستبدَل،
ومتغيّرات تُضبط، وإعادة تشغيل واحدة **لأجل المتغيّرات وحدها** — الملف نفسه لا
يحتاجها، لأن `docker-compose.yml` يربط المجلّد ربطاً حيّاً
(`./server/downloads:/app/downloads`) فما تكتبه على المضيف تخدمه الحاوية فوراً.

## ١. تأكّد أنّ الأرضية صحيحة قبل أن تلمس شيئاً

```bash
cd <app-dir>
git log --oneline -1
curl -s https://munasbat.ktra-pro.tech/api/services/categories
curl -s https://munasbat.ktra-pro.tech/api/app/version
```

يجب أن يكون الالتزام `0534f85` أو أحدث، وأن يردّ مسار الفئات بمصفوفة (فارغة
غالباً) **لا بـ404**.

**إن ردّ بـ404: قف وأبلغ.** يعني الخادم لم يُحدَّث بعد، ورفعُ تطبيق يطلب مسارات
غير موجودة يكسره عند كل مستخدم يفتح تاب الخدمات.

سجّل ما يعيده `/api/app/version` الآن — ستقارن به في النهاية.

## ٢. تحقّق من الملف الواصل قبل أن تعتمده

```bash
ls -lh /tmp/negev-events-1.2.0.apk
sha256sum /tmp/negev-events-1.2.0.apk
```

**قارن البصمة بالتي أعطاك إياها المالك.** إن اختلفتا فالنقل ناقص أو تالف —
**قف، واطلب إعادة الرفع**. لا تكمل ببصمة غير مطابقة.

## ٣. احتفظ بالقديم

```bash
cp server/downloads/negev-events.apk ~/negev-events-1.1.0.apk.bak
ls -lh ~/negev-events-1.1.0.apk.bak
```

هذه نقطة تراجعك الوحيدة لملف التطبيق. لا تكمل إن فشلت.

## ٤. انقله في مكانه

```bash
mv /tmp/negev-events-1.2.0.apk server/downloads/negev-events.apk
ls -lh server/downloads/negev-events.apk
sha256sum server/downloads/negev-events.apk
```

**الاسم يجب أن يبقى `negev-events.apk` حرفياً** — هو ما يشير إليه
`APP_APK_URL`، وتغييره يكسر رابط التنزيل عند كل مستخدم.

البصمة بعد النقل يجب أن تطابق التي تحقّقت منها في الخطوة ٢.

## ٥. اضبط المتغيّرات

في `.env` بجانب `docker-compose.yml`:

```env
APP_LATEST_VERSION=1.2.0
APP_APK_URL=https://munasbat.ktra-pro.tech/downloads/negev-events.apk
APP_RELEASE_NOTES=تاب «الخدمات» الجديد · اختيار القرية عند النشر · اسم الفنان على كرت العرس
```

⚠️ **`APP_MIN_VERSION` يبقى فارغاً. لا تضبطه، ولا تنسخ إليه رقم النسخة.**

هذا قرار لا سهو: كل ما في الخادم الجديد **إضافة**، فنسخة 1.1.0 تظل تعمل — بل إنها
تحصل على دبّوس صحيح لمناسبات القرى **بلا تحديث إطلاقاً**، لأن الخادم يرسل
الإحداثيات محسوبة. ضبطُ `APP_MIN_VERSION` يحبس مستخدماً خارج تطبيق يعمل عنده،
مقابل لا شيء.

إن وجدت `APP_APK_URL` مضبوطاً على قيمة مختلفة تعمل اليوم، **أبقِها كما هي وأبلغ**
بدل أن تستبدلها بما هنا.

## ٦. أعد التشغيل — للمتغيّرات

```bash
docker compose up -d app
docker compose logs --tail=30 app
```

## ٧. التحقّق

```bash
# النسخة المعلنة تغيّرت، وmin_version فارغ
curl -s https://munasbat.ktra-pro.tech/api/app/version

# رابط التنزيل حيّ، والحجم كامل (لا 0 ولا صفحة خطأ)
curl -sI https://munasbat.ktra-pro.tech/downloads/negev-events.apk | head -5
```

المتوقَّع: `1.2.0` في الأول، و`200` مع `Content-Length` نحو ٥٥–٥٨ مليون بايت في
الثاني، و**`min_version` فارغاً أو غائباً**.

إن ظهر `min_version` بقيمة، **أزلها من `.env` وأعد التشغيل** — تلك حالة تحبس
مستخدمي 1.1.0 خارج تطبيق يعمل.

## ٨. التراجع

```bash
cp ~/negev-events-1.1.0.apk.bak <app-dir>/server/downloads/negev-events.apk
# ثم أعد APP_LATEST_VERSION إلى 1.1.0 في .env
docker compose up -d app
```

الملف يعود فوراً بلا إعادة تشغيل؛ إعادة التشغيل لأجل المتغيّر وحده.

## أبلغ في النهاية

البصمة قبل الرفع وبعده · ما كان يعيده `/api/app/version` وما صار يعيده · حجم
الملف من ترويسة التنزيل · وتأكيداً صريحاً أن `APP_MIN_VERSION` بقي فارغاً.
